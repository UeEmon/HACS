# 自動更新・鍵管理・プリセット

全体の接続関係は [システム構成図](system-architecture.md) を参照してください。

実装対象は16音／32音の機番号変換、WAV生成、受信シミュレータ。実無線機へのコード設定・音声・PTTインターフェースは引き続き保留。

## 自動更新付きDocker起動

Python 3.10以降とDocker Composeを使用する。Windows・Mac・Linuxで同じCompose構成。

```bash
python3 generate_key.py --output .secrets/admin.token
docker compose -f compose.yaml -f compose.rotation.yaml up --build -d
```

初回はサーバーが256ビットの親鍵を生成し、共有ボリューム `hacs_keys` のSQLiteストアへ保存する。送信部が書込み、受信部は読取り専用で利用する。管理トークンは親鍵とは別の乱数値で、Docker secretとして送信部だけへ渡す。生成スクリプトは既存ファイルを上書きしない。

管理トークンを参照する場合は端末で `.secrets/admin.token` を開き、送信画面の管理欄へ入力する。Gitやチャット、画面共有に貼り付けない。POSIX環境では保存ディレクトリを700にし、コンテナが読むファイルは読取り専用にする。Windowsでは保存先のNTFSアクセス権で他の利用者から保護する。

更新周期は `.env` に設定する。鍵そのものは `.env` に書かない。

```text
HACS_ROTATION=daily
```

| 値 | JSTの切替日時 |
|---|---|
| daily（既定） | 毎日00:00 |
| weekly | 毎週月曜日00:00 |
| monthly | 毎月1日00:00 |

周期の変更後は同じComposeコマンドで2サービスを再作成する。送信部のURLは http://localhost:8787、受信部は http://localhost:8788。画面に周期、期間、次回更新、鍵識別子を表示する。両画面の鍵識別子と期間を確認する。定期切替は親鍵から期間鍵を導出するもので、親鍵の漏えい対応は次の即時更新で行う。

停止する際もComposeファイルを両方指定する。

```bash
docker compose -f compose.yaml -f compose.rotation.yaml down
```

`down` だけでは保存データを消さない。`down -v` は親鍵とプリセットの保存ボリュームを削除するため使用しない。ボリュームを失うと再起動時に新しい鍵となり、従来コードを復元できない。バックアップは鍵ストアを含む秘密情報として保護する。

## 呼び出し先プリセット

送信画面の「プリセットの登録・編集」で名称を入力し、機番号と方式を指定して「新規登録」を押す。登録後は「呼び出し先プリセット」から選択するだけで機番号・方式が入る。受信設定コードを確認して音声を生成する。選択だけでは音声を再生しない。

選択した項目は名称、機番号、方式を変更して「選択項目を更新」で保存できる。「削除」は確認後にその項目を消す。同じ機番号・方式は重複登録できない。同じ機番号を16音と32音で別々に登録することは可能。

保存するのは名称・機番号・方式だけ。鍵や呼び出しコードはプリセットへ保存せず、期間・親鍵を更新しても登録した機体を選び直せる。Dockerでは `hacs_data` に保存し、再起動後も残る。Pythonでの直接起動は既定でリポジトリ内 `data/` に保存する。いずれもGit対象外。

## 漏えい時の共通鍵更新

1. 送信画面の「共通鍵の管理」を開く。
2. 管理トークンを入力し、理由「漏えい対応」を選ぶ。
3. 「新しい共通鍵へ即時切替」を押し、確認する。
4. 更新後の鍵識別子を両画面で確認し、現在の受信設定コードで音声を再生成する。

新しい独立した256ビット親鍵を生成し、共有ストアの有効鍵を置換する。日・週・月の次の切替時刻を待たない。両サービスの次の処理は新しい鍵を読む。ブラウザは更新状態を検出すると旧音声を無効化し、再生・保存直前にも確認する。実受信装置は新しいコードへ別途設定する。別PC・別Docker環境への安全な鍵配布は今回自動化していない。

管理トークンは操作後に入力欄から消し、ブラウザへ永続保存しない。「更新履歴を表示」では世代、識別子、更新日時、理由を確認できる。履歴に鍵そのものを残さない。旧鍵の復活・旧鍵へ戻す操作は提供しない。バックアップからの復旧で失効鍵を再有効化しないよう管理する。

管理トークン自体が漏えいした場合は、専用ファイルを安全に再生成・置換して送信サービスを再作成する。親鍵だけの更新では管理トークンは変わらない。

## 保存WAVの期間指定

鍵付きWAVの名前と追加チャンクには期間ID・鍵識別子を含める。PCM音声とSELCAL送信形式は変えない。受信シミュレータで以前の期間のWAVを試す場合は、画面の「保存WAVの生成期間」に `D-2026-10-12`、`W-2026-10-12`、`M-2026-10` のように入力する。

空欄では現在の期間のみを使用する。期間が違う保存ファイルは自動的に旧期間へ切り替えず、再指定を求める。親鍵を変更した後は、失効鍵で生成したWAVを拒否する。WAVに含む情報は署名されておらず、RF音声には入らないため、通信の認証やリプレイ防止を意味しない。

## Pythonでの構成

Dockerを使用しない場合も、同じ `HACS_KEY_STORE`、`HACS_ROTATION` を2サービスへ設定する。送信部には `HACS_KEY_CREATE=1` と `HACS_ADMIN_TOKEN_FILE`、受信部には `HACS_KEY_READONLY=1` を設定する。送信部を先に起動する。`HACS_DATA_DIR` でプリセット保存先を変更できる。

共有ストアを使わず `HACS_KEY_FILE` を指定するファイル方式も可能だが、画面からの親鍵更新には書込み可能な共有ストアが必要。CLIの機番号変換とWAV生成も現在の環境設定の鍵・周期を使用する。`tail_mapping.py` のPython関数は互換性維持のため基礎の鍵なし変換を提供し、期間付き処理は `rotation.configured_mapping().snapshot()` を使用する。

## 検証範囲

JST日付・週・月・年・うるう年の境界、両方式の10000件の鍵付き変換、共有ストアの再読込み・即時更新・失効WAV拒否、管理トークンとOriginの拒否、プリセット保存・重複防止・更新・削除をソフトウェア試験で確認する。画面側の期限・鍵識別子チェックはNode単体試験で確認する。Docker実行、各OSのブラウザ、実受信装置の試験はこの開発環境では未実施。

## プリセットの機番号・コード一覧出力

送信画面の「プリセットの機番号・コード一覧」で「一覧を表示」または「CSVを保存」を選びます。登録済みの名称・4桁機番号・方式・現在の呼び出しコードを出力します。16音と32音の登録先を一緒に出力できます。

一覧には期間、鍵識別子、作成日時（JST）、次回更新日時を表示します。CSVにはさらに変換方式のバージョンを各行に記載します。共通鍵の値は出力しません。1回の出力は同じ鍵・期間に固定して計算します。コードをプリセットデータベースに保存することはありません。

期間切替・共通鍵更新・画面からのプリセット変更時は表示中の一覧を消します。保存済みCSVは自動更新されないため、更新後に再出力してください。自動更新を無効にした場合は固定変換のコードを出力します。

CSVはUTF-8（BOM付き）です。機番号は`0000`のような4文字で出力します。ExcelではCSVの取り込み時に機番号列を「文字列」に指定してください（直接開くと先頭の0が省略される場合があります）。名称が数式として解釈される文字で始まる場合は、CSV上で先頭にアポストロフィを付けます。未登録時はヘッダーだけのCSVになります。

API: `GET /api/presets/codes`（JSON）、`GET /api/presets/export.csv`（CSV）。必要に応じて`period_id`と`key_id`を指定すると現在値との不一致を拒否します。これらのAPIもローカル利用を前提とします。
