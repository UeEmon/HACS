# 呼び出し相手先変換アルゴリズム HACS-TN16-v1

## 対象と条件

入力はテールナンバーとして使用する4桁の半角数字文字列 `0000`〜`9999`。数値型では受け付けず、先頭のゼロを保持する。出力は従来16音のSELCALコード形式。数字を音に直接割り当てるのではなく、4桁全体の番号を有効コードの列挙順位に変換する。

HACS独自の対応規則であり、ASRIによる航空機のコード割り当て規則ではない。実機の設定済みコードと自動的に一致するものではない。既存航空機を呼び出すには、当該機の実コードとの照合、あるいは呼び出し相手先と実コードの対応表が必要。無線機インターフェースは保留中。

## 列挙規則

1. 音文字を `A B C D E F G H J K L M P Q R S` の順に固定する。
2. 第1組は16文字から2文字を選び、組内を文字順とする。組は辞書順に列挙する（120通り）。
3. 第1組の2文字を除いた14文字から、第2組を同様に列挙する（91通り）。
4. 第1組の位置を `i`、第2組の位置を `j` とすると、全体の順位は `91 × i + j`。

位置は0から数える。第1組と第2組の順序は区別する。例えば `AB-CD` と `CD-AB` は異なるコード。

## 順変換

呼び出し相手先を整数 `n` に読み替え、`i = n // 91`、`j = n % 91` を計算する。第1組の `i` 番目を選び、その組の文字を除いた第2組の `j` 番目を選ぶ。

## 逆変換

コードの4文字・使用文字・重複禁止・組内順序を検証する。第1組と第2組の列挙位置から `n = 91 × i + j` を復元する。`n < 10000` であれば、4桁ゼロ埋め文字列に戻す。10000〜10919は未割当として拒否する。

## 重複しない理由

有効なコード数は `C(16,2) × C(14,2) = 120 × 91 = 10920`。異なる第1組は異なる `i`、同じ第1組の異なる第2組は異なる `j` となる。商と余りは一意なので、先頭10000個への割り当てで衝突は発生しない。ハッシュや剰余だけでコードを作る方式は使用しない。

## 変換例

| 呼び出し相手先 | 第1組位置 i | 第2組位置 j | コード |
|---|---:|---:|---|
| 0000 | 0 | 0 | AB-CD |
| 0001 | 0 | 1 | AB-CE |
| 5501 | 60 | 41 | EM-DL |
| 9999 | 109 | 80 | LS-JR |

## 実装と運用

実装は `tail_mapping.py`。対応表ファイルやDBは不要。第2組の列挙結果を最大120組キャッシュする。列挙順序・文字順序は固定し、変更時は別バージョンとして扱う。送受信で同じ `HACS-TN16-v1` を使う必要がある。バージョン番号はAPIで返すが、従来SELCAL音声信号には追加情報として送信しない。

全10000入力の有効性・重複なし・逆変換一致、残り920コードの拒否、入力エラー、呼び出し相手先→音声→受信→呼び出し相手先の一連処理を試験する。

4桁が同じ機体を同一の通信網で区別することはできない。HACS内の一意性は入力4桁に対する一意性であり、世界中の航空機や既存SELCALコード割当との一意性を意味しない。
