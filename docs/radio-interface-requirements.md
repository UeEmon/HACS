# 無線機インターフェース作成に必要な項目

本書はHACSの既存実装と接続方式の検討を整理した、機種別設計・資料収集・実装のチェックリストです。メーカー固有の端子値や制御コマンドは対象機の資料で確定します。未確認値を汎用値で補完しません。

## 1. 最初に決める事項

| 項目 | 確定する内容 | 成果物 |
|---|---|---|
| 対象装置 | メーカー、型式、オプション、ファームウェア、外部制御装置の有無 | 対象機器一覧 |
| 実装範囲 | 音声注入とPTTのみか、状態取得・音声源選択・周波数等の設定まで扱うか | 制御機能一覧 |
| 音声経路 | アナログ音声、機器指定のネットワーク音声、または機器内信号生成 | 音声経路図 |
| 制御経路 | 接点／RTS・DTR変換、機種固有シリアル、Ethernet API、1553 | 制御経路図 |
| 実行場所 | 無線機に接続したホスト、専用ゲートウェイ、直接接続のいずれか | 配置・接続図 |
| 動作環境 | Windows／macOS／Linux、CPU、USB機器、ドライバ・SDK対応 | 対応環境表 |
| 送信確認の範囲 | コマンド受付、PTT出力、装置の送信状態、音声出力、受信側検出のどこまで取得可能か | 状態定義 |

音声経路と制御経路は別々に確定します。「Ethernet端子がある」「1553対応」だけでは音声送信・PTT操作が可能とは判断できません。

## 2. 収集が必要な資料

- 外部インターフェース仕様書／ICD、取扱説明書、該当ファームウェアの変更履歴。
- コネクタのピン配置図、電気特性、推奨接続回路、対応ケーブルの資料。
- 制御プロトコル、コマンド・応答一覧、状態・異常コード、通信タイミング。
- 接続変換器・音声装置・ゲートウェイの仕様、ドライバ／SDK、使用条件。
- 制御要求と応答のサンプル、可能であればメーカーの試験手順。

各値には資料名・版・ページと、実測による確認の有無を記録します。製品紹介や調達一覧で型式が判明しても、接続仕様が確定した扱いにはしません。

## 3. 共通で必要な技術項目

| 分類 | 設計・確認項目 | HACSで決める内容 |
|---|---|---|
| コネクタ・配線 | 型番、ピン、信号方向、リターン、シールド、接地、ケーブル長 | 配線図・ケーブル仕様 |
| 音声入力 | 平衡／不平衡、入力インピーダンス、標準・最大入力、許容帯域、DC成分、絶縁 | 出力回路、減衰量、接続方式 |
| 音声処理 | フィルタ、AGC、コンプレッサ、ノイズ処理、入力源の選択 | トーンの振幅・周波数・時間を維持する設定 |
| PTT入力 | 接点／電圧／コマンド、有効極性、開放電圧、必要電流、絶縁 | 機種適合回路・ドライバ |
| PTTタイミング | 送信準備時間、前後待ち、解除時間、連続送信上限 | 前待ち・後待ち・上限の実測値 |
| 状態取得 | 接続状態、送信許可、BUSY、PTT、装置異常 | 取得可能な状態だけをWebに表示 |
| 音声出力完了 | バッファ投入とデバイス再生完了の区別 | 再生完了後に後待ち・PTT解除 |
| 障害時動作 | 通信断、プロセス停止、USB抜去、応答消失、二重要求 | 中断、解除、再接続、再送の条件 |
| 鍵・期間 | 実行時点の有効コードと更新境界 | 古い期間・鍵のジョブ拒否、再生成要求 |

現在のHACS生成音声は48 kHz・16 bit・モノラル、2音1秒＋無音0.2秒＋2音1秒です。実機の入力経路がこの信号を保持できるか確認します。現在の前待ち0.3秒・後待ち0.2秒・PTT上限5秒は汎用初期値であり、対象機の保証値ではありません。

## 4. 出力レベルの校正

Webの1〜90%はデジタル音声振幅です。端子電圧やRF出力を直接指定する値ではありません。

| 確認段階 | 必要な値・条件 |
|---|---|
| HACS | 出力レベル%、コード方式、生成WAV |
| ホスト音声装置 | デバイス名／ID、チャンネル、OS音量、ミキサ・音声効果の設定 |
| 接続回路 | 減衰、利得、絶縁、負荷条件 |
| 無線機入力端子 | メーカー指定条件での実測レベル、クリッピング、2音の相対レベル |
| 無線機側 | 入力源、入力利得、関連する音声処理、適正変調の確認方法 |

「HACSの設定値 → 実測した無線機入力レベル」の対応を校正記録として保存します。音声装置・OS音量・接続回路・無線機入力利得が変わった場合は再確認します。レベル変更時はWAVを再生成します。

## 5. 接続方式別の追加項目

| 方式 | 必要な追加情報・機材 | 未確定なら実装を進められない事項 |
|---|---|---|
| 音声＋RTS/DTR PTT | 音声装置、ローカルポート、制御線、論理、無線機用変換回路、ポート開閉時の挙動 | 無線機端子の電気特性・ピンと変換回路 |
| シリアルデータ制御 | RS-232/422/485等の規格、速度、データビット、パリティ、ストップビット、フロー制御、アドレス、区切り、チェックサム、コマンド・応答 | PTT ON/OFF・状態取得の機種固有定義 |
| Ethernet直接接続 | 接続先・ポート、トランスポート、API、認証、セッション、音声形式、バッファ、期限、再接続 | 実機の制御APIと音声転送仕様 |
| Ethernetゲートウェイ | 接続先、認証、ジョブID、事前転送、取消・状態照会、時刻同期、現地音声/PTTドライバ | ゲートウェイAPIと実機側接続仕様 |
| MIL-STD-1553 | 適用版・ICD、BC/RT役割、アドレス、サブアドレス、方向、ワード数・データ定義、周期、A/B系、カード／SDK | 対象機のメッセージ定義と既存BCとの接続計画 |

RTS/DTRだけの操作にはボーレート設定を使用しません。シリアルデータとRTS/DTRを同じポートで扱う場合は、ポート管理とフロー制御の競合を確認します。1553で制御する場合も音声経路は別途定義します。装置内でトーンを生成する方式は、装置側の対応と制御仕様が確認できた場合に限ります。

## 6. Webから接続・送信まで完結させるための追加開発

現在のWeb設定は保存とJSON出力までです。Webからの実接続・送信には、次の実装が必要です。

| 項目 | 実装する内容 |
|---|---|
| ホストサービス／ゲートウェイ | 接続機器のドライバを保持し、HACSからの要求を処理する常駐サービス |
| 機器列挙 | 実行ホスト上の音声・シリアル機器を列挙し、保存機器の存在を確認 |
| 接続ライフサイクル | 設定検証、接続、切断、再接続、装置排他、送信中の設定変更抑止 |
| API | 状態照会、設定適用、接続・切断、WAV受渡し、実行・中断、結果取得 |
| 認証・権限 | 呼び出し操作と接続設定変更の権限、サービス間認証、通信保護。コード変換用共通鍵とは分離 |
| ジョブ制御 | 一意ID、期限、重複実行防止、音声検証、鍵・期間確認、実行状態の保存 |
| 異常処理 | 応答不明時の状態照会、現地PTT上限・解除、異常時の送信抑止 |
| Web状態表示 | 未接続／接続中／待機／送信中／異常。取得できない状態は不明と表示 |
| 履歴 | 要求・開始・音声出力完了・PTT解除・失敗のサーバ側記録とジョブID。実受信成功とは区別 |
| 配布・運用 | OS別インストール、ドライバ／SDK、起動設定、ログ、更新手順 |

Docker上の本体からホストのUSB機器が自動で見えるとは扱いません。Windows・macOS・Linux共通化を重視する場合、機器に近いホストサービスへOS依存処理を分離する構成を検討します。

## 7. 現在のHACS実装との対応

| 項目 | 現状 |
|---|---|
| Webでの音声・PTT・時間・出力レベル設定 | 実装済み。サーバ保存、再読込、JSON出力 |
| 16/32音のWAV生成・内部確認 | 実装済み |
| ホスト音声出力＋RTS/DTRドライバ | 実装済み。ホストCLIから明示実行。実機未検証 |
| 無線機・航空機受信エミュレータ | 実装済み。WAVを使う模擬通信 |
| Webから実機へ接続／切断・直接送信 | 未実装 |
| ホスト機器一覧のWeb取得 | 未実装 |
| CAT等のシリアルコマンド、実機Ethernet、1553 | 機種別仕様待ち・未実装 |
| 個別機種の電気回路・端子レベル保証 | 未確定、個別確認が必要 |

## 8. 試験項目と完成判定

| 段階 | 試験項目 | 合格条件の決め方 |
|---|---|---|
| 設定検証 | 欠落、範囲外、機器不在、設定競合、再起動後の保存値 | 不正設定で出力を開始しない |
| エミュレータ結合 | 正常、BUSY、拒否、タイムアウト、切断、重複・期限切れ | 状態遷移と実行回数が定義どおり |
| 音声・PTT端子 | 音声レベル、2音、時間、PTT前後待ち、解除 | 対象機の許容値と設計値で実測確認 |
| 障害注入 | USB抜去、ネットワーク切断、サービス停止、応答消失 | 現地解除方法・上限・再開条件を確認 |
| 鍵・時刻 | JST更新境界、鍵更新、秘匿ON/OFF、時計ずれ | 古い音声・期限切れ要求の扱いが設計どおり |
| 実機・受信装置 | 対象機を通した16/32音の呼び出しと受信検出 | 対応する実受信装置で判定。非対応方式は別扱い |
| OS・運用 | 対象OS、再起動、機器再接続、長時間運転 | 対応環境ごとの記録を残す |

具体的な許容誤差・時間上限は対象機資料と要求仕様から確定します。ソフトウェア単体試験やエミュレータの成功だけで、電気的適合・RF経路・実受信を確認済みとはしません。

## 9. 機種別に埋める記入票

| 項目 | 記入内容 |
|---|---|
| メーカー／型式／FW／オプション | 未確定 |
| 使用資料／版／ページ | 未確定 |
| 実装する制御機能 | 未確定 |
| 音声経路／端子／入力特性 | 未確定 |
| PTT経路／端子／電気特性 | 未確定 |
| 状態取得の方法／取得可能な状態 | 未確定 |
| 変換器／接続回路／ケーブル | 未確定 |
| ホストOS／機器ドライバ／SDK | 未確定 |
| プロトコル／コマンド／応答 | 未確定または該当なし |
| 前後待ち／PTT上限／異常解除 | 未確定 |
| 出力レベル校正値／測定条件 | 未確定 |
| 実装担当範囲／試験環境／合格基準 | 未確定 |

対象機が確定するまでは、[標準アナログ無線機仕様](standard-analog-radio-spec.md)の基準値と適合条件で設計・試験を進めます。確定後は、この記入票と標準の条件を照合し、標準適合か差分ありかを記録します。

着手順は、対象機と資料の確定 → 音声・制御経路と配線の確定 → 機種別アダプタ／ホストサービス → 模擬試験 → 端子計測 → 実機・受信試験とします。

関連：[汎用音声・PTTとWeb設定](generic-radio-interface.md)、[接続方式別の検討](radio-transport-options.md)、[構成図](system-architecture.md)、[エミュレータ](emulators.md)。
